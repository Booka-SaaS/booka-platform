# GitHub Projects — Kanban da Crise

## Nome do Project

Booka — EC2 Dia do Caos na Squad

## Objetivo

Este GitHub Project deve organizar a simulação de crise em produção do Booka, permitindo acompanhar em tempo real as tarefas relacionadas ao hotfix, investigação do erro, otimização do banco de dados, Pair Programming, Merge Conflict, Code Review, testes e Postmortem.

## Colunas Obrigatórias

1. Backlog
2. A Fazer
3. Em Desenvolvimento
4. Em Revisão
5. Testes
6. Concluído
7. Bloqueado

## Regras do Kanban

- Todo card deve ter responsável.
- Todo card deve ter descrição clara.
- Todo card deve ter critério de aceite.
- Cards em desenvolvimento devem estar relacionados à branch `hotfix/broken-checkout`.
- Cards só podem ir para “Concluído” após validação.
- Cards bloqueados devem ter justificativa.
- O Product Owner deve validar os cards principais antes do fechamento.

## Relação com a Avaliação

O Kanban atende ao critério de “Uso de Ferramentas”, pois demonstra que a equipe organizou o fluxo da crise, respeitou o Gitflow e acompanhou a evolução das tarefas.
